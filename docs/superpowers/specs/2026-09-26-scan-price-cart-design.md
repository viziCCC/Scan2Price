# 扫码查价与价格清单功能设计

## 1. 背景与目标

本项目是商铺内部使用的微信小程序。使用者通过扫描商品条形码查询自建商品库中的当前价格，并将多个商品加入临时价格清单，调整数量后计算总价。

系统不面向顾客，不包含下单、支付、收货地址、订单管理和库存扣减。商品资料由少量管理员直接在小程序端维护。

第一版目标是完成以下闭环：

1. 管理员录入和维护商品。
2. 员工扫描或手动输入条形码查询价格。
3. 将商品加入临时价格清单。
4. 调整整数数量并计算小计和总价。

## 2. 用户角色

### 2.1 普通员工

- 扫描商品条形码。
- 手动输入条形码。
- 查看商品名称、规格、单位和价格。
- 将在售商品加入价格清单。
- 在价格清单中继续扫码、修改数量、移除商品和清空清单。
- 不显示商品管理入口。

### 2.2 管理员

管理员拥有普通员工的全部能力，并可：

- 查看和搜索商品列表。
- 扫码或手动录入商品。
- 编辑商品资料和价格。
- 上架或下架商品。

管理员身份采用 OpenID 白名单，由维护者直接在微信云开发控制台的 `admins` 集合中配置。第一版不开发管理员管理页面。

## 3. 总体架构

项目继续使用微信云开发，不新增传统服务器。

```text
小程序端
├─ 扫码查价首页
├─ 商品查询结果
├─ 临时价格清单
└─ 商品管理（仅管理员显示）
   ├─ 商品列表
   └─ 商品录入/编辑

云函数
├─ getCurrentUser
├─ getProductByBarcode
├─ listProducts
├─ createProduct
├─ updateProduct
└─ changeProductStatus

云数据库
├─ products
└─ admins
```

云函数沿用当前单一入口按 `event.type` 分发的部署方式，但内部应按权限、商品查询和商品管理职责拆分函数，避免入口文件继续膨胀。

## 4. 页面设计

### 4.1 扫码查价首页

- 显示主要操作“扫码查价”。
- 提供手动输入条形码入口。
- 查询成功后展示商品名称、规格、单位和价格。
- 提供“加入价格清单”操作。
- 显示当前价格清单总件数，并可进入价格清单。
- 管理员显示商品管理入口；普通员工不显示。

### 4.2 价格清单

- 页面顶部或明显位置提供“扫码添加”入口。
- 扫码成功后停留在当前页面，便于连续扫描。
- 同一商品重复扫描时，不创建重复行，直接将数量加一。
- 每项展示商品名称、规格、单价、数量和小计。
- 数量仅允许正整数。
- 提供数量减少、数量增加和移除操作。
- 数量为一时继续减少，应提示是否移除该项。
- 实时展示总件数和总金额。
- 提供“清空清单”，执行前二次确认。
- 清单仅保存在当前小程序运行内存中，不写入本地缓存或云数据库。

### 4.3 商品管理列表

- 仅管理员可以进入。
- 支持按商品名称或条形码搜索。
- 支持筛选在售和已下架商品。
- 点击商品进入编辑页面。
- 提供“扫码录入”和“手动录入”两个入口，默认突出扫码录入。

### 4.4 商品录入/编辑

- 扫码录入通过 `wx.scanCode()` 获取条形码。
- 手动录入允许管理员直接输入条形码。
- 扫码或输入后先检查条形码是否已存在。
- 条形码不存在时进入新增表单。
- 条形码已存在时提示并进入该商品编辑页面，不创建重复记录。
- 表单字段包括条形码、商品名称、价格、规格、单位、商品图片、备注和商品状态。
- 商品名称、条形码和价格必填，其他字段选填。
- 支持保存、上架和下架。
- 第一版不提供物理删除。

## 5. 数据模型

### 5.1 products 集合

```js
{
  _id: "云数据库自动生成",
  barcode: "6901234567890",
  name: "可口可乐",
  priceInCents: 350,
  specification: "500ml",
  unit: "瓶",
  imageFileId: "cloud://...",
  status: "on_sale",
  remark: "",
  createdBy: "管理员 OpenID",
  createdAt: Date,
  updatedBy: "管理员 OpenID",
  updatedAt: Date
}
```

约束：

- `barcode` 按字符串存储，以保留可能存在的前导零。
- `barcode` 在业务上必须唯一，新增前由云函数检查。
- `priceInCents` 以人民币分为单位存储，必须是大于或等于零的整数。
- `status` 仅允许 `on_sale` 或 `off_sale`。
- 已下架商品保留在数据库中，不物理删除。

### 5.2 admins 集合

```js
{
  _id: "云数据库自动生成",
  openid: "管理员 OpenID",
  name: "管理员名称",
  enabled: true,
  createdAt: Date
}
```

只有 `enabled` 为 `true` 的记录具有管理员权限。

### 5.3 价格清单内存模型

```js
{
  productId: "商品记录 _id",
  barcode: "6901234567890",
  name: "可口可乐",
  specification: "500ml",
  unit: "瓶",
  priceInCents: 350,
  quantity: 2
}
```

小计为 `priceInCents * quantity`。总件数为所有 `quantity` 之和，总金额为所有小计之和。页面展示时将分转换为元并保留两位小数。

商品加入清单时复制当时的价格。管理员之后修改商品价格，不追溯更新已经加入清单的项目；重新扫描或重新加入后才读取最新价格。

## 6. 云函数接口

### 6.1 getCurrentUser

- 获取调用者 OpenID。
- 查询 `admins` 集合。
- 返回 `{ openid, isAdmin }`。

### 6.2 getProductByBarcode

- 输入条形码字符串。
- 查询 `products` 集合。
- 普通查询只返回在售商品。
- 管理员录入流程可查询在售和已下架商品，用于识别重复条码。

### 6.3 listProducts

- 仅管理员调用。
- 支持关键词、状态、分页参数。
- 关键词匹配商品名称或精确条形码。

### 6.4 createProduct

- 仅管理员调用。
- 校验必填字段、价格和状态。
- 校验条形码不存在。
- 写入创建人、更新人和时间字段。

### 6.5 updateProduct

- 仅管理员调用。
- 根据商品 `_id` 更新允许修改的字段。
- 如允许修改条形码，必须再次校验唯一性。
- 更新 `updatedBy` 和 `updatedAt`。

### 6.6 changeProductStatus

- 仅管理员调用。
- 将状态切换为 `on_sale` 或 `off_sale`。
- 不删除商品记录。

## 7. 权限与安全

- 前端根据 `isAdmin` 控制商品管理入口的显示。
- 前端隐藏入口不是安全边界。所有管理接口均必须在云函数中重新查询 `admins` 集合并校验权限。
- 普通员工即使手工构造云函数请求，也不能新增、修改或上下架商品。
- 数据库写权限应尽量关闭客户端直写，商品修改统一通过云函数完成。
- 云函数只接受白名单字段，不能直接将整个客户端对象写入数据库。
- 条形码、名称、价格、数量和状态均需在服务端校验。

## 8. 主要业务流程

### 8.1 普通扫码查价

1. 员工点击扫码。
2. 小程序获得条形码字符串。
3. 调用 `getProductByBarcode`。
4. 找到在售商品时展示价格。
5. 员工选择加入价格清单。
6. 商品已存在于清单时数量加一，否则新增一项。

### 8.2 价格清单连续扫码

1. 员工在价格清单点击“扫码添加”。
2. 查询商品。
3. 商品存在且在售时加入或增加数量。
4. 页面停留在价格清单并刷新总件数和总金额。
5. 员工可以继续扫描下一个商品。

### 8.3 管理员录入商品

1. 管理员进入商品管理。
2. 默认选择扫码录入，也可切换手动录入。
3. 系统先查询条形码。
4. 条形码已存在时进入编辑页面。
5. 条形码不存在时进入新增页面并预填条形码。
6. 管理员填写资料并提交。
7. 云函数验证管理员身份和数据后写入商品。

## 9. 异常处理

- 用户取消扫码：不显示错误，保持当前页面状态。
- 无法识别条形码：提示重新扫描或手动输入。
- 商品不存在：普通员工提示未录入；管理员额外提供录入入口并预填条形码。
- 商品已下架：提示商品已下架，不能加入清单。
- 网络或云函数失败：提示稍后重试，保留现有价格清单。
- 条形码重复：禁止新增，引导管理员编辑现有商品。
- 权限不足：提示无管理员权限，不泄露管理数据。
- 表单校验失败：在具体字段附近显示原因。
- 图片上传失败：保留表单内容，允许重新上传或暂不上传。

## 10. 非目标

第一版明确不包含：

- 顾客端商城。
- 微信支付。
- 订单和结算记录。
- 库存数量和库存扣减。
- 会员、收货地址或优惠券。
- 跨设备同步价格清单。
- 退出小程序后恢复价格清单。
- 商品物理删除。
- 管理员管理页面。
- 第三方条码商品信息接口。

## 11. 验收标准

1. 管理员可以扫码或手动录入商品。
2. 重复条形码不会产生两条商品记录。
3. 普通员工看不到商品管理入口。
4. 普通员工直接调用管理接口会被云函数拒绝。
5. 扫描已录入且在售的商品能正确显示价格。
6. 扫描未录入商品能得到明确提示。
7. 已下架商品不能加入价格清单。
8. 价格清单页面可以继续扫码添加商品。
9. 重复扫描同一商品时数量自动增加。
10. 数量只能是正整数。
11. 单项小计、总件数和总金额计算正确。
12. 金额计算以分为单位，不出现浮点误差。
13. 可以移除单项并二次确认清空清单。
14. 退出小程序后价格清单不会恢复。
15. 管理员可以编辑商品并执行上架或下架。

## 12. 测试范围

- 云函数权限校验测试：普通员工和管理员分别调用管理接口。
- 商品字段校验测试：空名称、非法价格、空条码、重复条码和非法状态。
- 商品查询测试：在售、下架和不存在三种结果。
- 价格清单计算测试：首次加入、重复扫码、数量加减、移除和清空。
- 金额测试：多商品、多数量和边界价格。
- 页面流程测试：扫码取消、扫码失败、网络失败和管理员录入跳转。
